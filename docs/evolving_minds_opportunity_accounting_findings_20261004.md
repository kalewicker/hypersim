## What the proposed sign criterion permits

The proposal fixes eight held-out worlds and threshold 0.025 per comparison. Computed exact sign tails are **9/256 for seven positives**, which fails, and **1/256 for eight**, which passes that criterion. Ties and nonpositive differences count against passage. With homogeneous independent-world positive probability p, the sign-count probability is p to the eighth power. This sensitivity model is not fitted to the exposed ecology and is not a scientific power estimate.

## Comparator clarification and next implementation

The original H3a proposal's third arm retains **each founder's first admitted request proposal**. Later notes called it an “initial-program draw”; that wording described a different comparator and is corrected by this package. It is neither a newly sampled founder genotype nor a new proposal on every later request. The unchanged delayed founder acts/develops normally, and a founder with no admitted request has no sample and stays in the denominator.

The next native package must sample SourceKernel once at that first paid request, retain the complete proposal/draw provenance for the founder's remaining requests, and make descendants copy their own inherited genotype faithfully. An invalid retained proposal remains invalid on every later founder request, paying charge and refunding unused escrow; unreachable retained offspring remain paid failed seeds. There is no redraw, repair or viable substitute. Checkpoints must retain this host comparator state in a new explicit version, including after a sampled founder dies; old formats keep their original meanings. Native/independent fixtures must cover repeated requests, rejection, unreachable development, no-request founders and exact process continuation before a new-world pilot.

Only after that implementation should a new contract freeze all five matched arms on development worlds 101/103/107/109, full opportunity/control thresholds and the resource/power decision.
