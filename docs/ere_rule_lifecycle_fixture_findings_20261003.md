## Why the edit is a real body change

The ordinary world is a three-node labelled path, with labels10/11/12. The core
changes path->star; the initialized proposal changes star->path but requires
label99 rather than10, so it cannot initially match this world.

At completed step1, a paid native edit changes the proposal's graph-resident
label constraint99->10. The new candidate has different exact and zero-priority
RCF bytes from both initialized candidates. It can now match the existing
ordinary star and actually turn it back into a path. Neither ordinary node
labels nor world state are edited by the host during execution.

This distinction matters: existing activation/restoration operators would use
or recover a known body, while Transpose changes slot presentation in an
unordered-edge world. Neither is silently credited as this fixture's new body.
The fixture instead uses an **explicitly seeded paid editor** through the
existing `GraphRuleSource.editors` seam. Its typed token and marker are declared
scaffolding. It is not a new admitted graph opcode, evolved instruction or
spontaneously invented editing language. Every editor/tick event is excluded
from ordinary rule novelty and nontrivial firing credit.

## Next useful step

This clears the engineering question: can a paid native edit create a
post-initialization body that is later admitted and used, with honest causal
controls and class-lifetime accounting? Yes, in this explicitly constructed
fixture. It does not yet ask a learner to choose an edit.

The next small implementation should expose **several paid edit choices** to a
bounded learning adapter and use post-birth ordinary firing—not initialized
proposal reuse—as the diagnostic outcome. Keep payment, frozen/no-edit and
preseeded controls, full initial-class exclusion and pre-step rule attribution.
Measure genotype/installed lifetime and censoring separately; do not invent a
half-life score from these short traces. Use a predeclared set of distinct
ordinary label contexts so the benchmark is not merely selecting this known
99->10 edit again. First validate that action/reward interface; then separately
register a small training budget. No larger gate-harness expansion is needed
before that interface test, and no scientific sustained-emergence claim is
authorized by the current result.
