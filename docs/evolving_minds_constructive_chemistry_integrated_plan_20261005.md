# Evolving Minds, constructive chemistry, and higher-order rewriting in Hypersim

**Integrated roadmap — 2026-10-05, America/Phoenix.** This is a planning revision, not an experiment contract or evidence of implementation. It preserves the existing Evolving Minds profiles and their results. The chemistry and higher-order extensions below are proposed.

## 1. Decision and document authority

Extend Hypersim through two explicitly versioned experimental profiles sharing the Rust graph, rule, engine, and evidence infrastructure:

- **Evolving Minds:** inherited programs, paid resource choices, development, and reproductive opportunity. Continue the existing bounded D0 work before changing its mutation operator.
- **Constructive chemistry:** conserved material, local reaction kinetics, physical copying and compartment reproduction, then conditional ecological and higher-order extensions.

The research connection is whether inherited material organization can construct useful behavior and new reproductive opportunities under fixed physical laws. The profiles do not initially share a physical economy. D0's instruction prices, ownership rules, child endowments, and tick schedule do not establish molecular conservation, physical fission, or chemistry.

This document governs **future ordering and cross-profile claim boundaries**. The [existing Evolving Minds plan](evolving_minds_hypersim_implementation_plan.md) retains its implementation history, H1/H2/H3 hypotheses, and profile-specific specifications. The [revised chemistry plan](constructive_chemistry_higher_order_hypersim_plan_20261005.md) supplies the proposed physical and software contracts. Sealed experiment contracts and findings remain authoritative for their own runs; neither new plan changes them retrospectively. Gate IDs below are the single roadmap index. Numerical acceptance thresholds belong in separately frozen prospective contracts.

The attachment is design input, not a request to execute its campaigns. This revision changes documentation only. No new scientific admission, training admission, sustained-innovation claim, world exposure, or native execution follows from integrating it.

## 3. Improvements to the supplied design

| Supplied design | Integrated revision and reason |
|---|---|
| Assumes patch-first execution already exists | Introduce and test an opt-in checked transaction seam; existing effect application can skip effects after structural changes |
| Fixed large spatial/population defaults | Start with bounded local patches; choose spatial size, population, and horizons only after measured resource and accessibility pilots |
| Six stages read as one compulsory success ladder | Separate engineering, ecology, operator, interpreter, collective, and scaling gates; a failed branch remains a result |
| Owner and compartment concepts appear interchangeable | Keep ownership guards in D0; use local material barriers and encounters in chemistry, with cell identity observer-derived |
| Conservation expressed as charges and fuel | Specify material vectors and a state-energy/reservoir ledger; reject overflow, double spending and unbalanced reactions atomically |
| Weighted reaction scheduling resembles existing modes | Define an explicit kinetic reference process; current rule weights and engine steps are not physical time |
| Global rule compilation treated as embodiment | Require the source motif to exist and qualify locally at every commit; installation in a shared table is insufficient |
| Sampled traces plus selected critical windows | Preserve complete compact semantic evidence from the first fixture; richer sampled views cannot replace it |
| Fissions counted as independent repetitions | Independent worlds are the main sampling units; within-world fissions and descendants are nested observations |
| Population-generation horizons based on observed performance | Freeze physical-time/event ceilings before confirmation; do not extend runs until enough survivors or generations appear |
| Multiple Stage 4 gates and dependency maps | One roadmap gate index; distinguish cumulative ecological chains from operator and translation mechanisms |
| Change universal operators if they dominate | Distinguish bugs from legitimate generalist dominance; retain valid negative results, redesign only in a new physics version |
| Raise operator bounds as simple scaling | Treat locality, action vocabulary and physical operator bounds as laws; varying them is a new scientific model |
| Operator counts and closure as broad novelty measures | Measure functional assays, time-resolved construction dependencies, and sampled accessible opportunities with explicit coverage |

## 6. Architecture and version boundaries

Keep composition in `hg-sim-core`, with the default-off `constructive-chemistry` feature and profile-specific schema/configuration. Reuse `hg-core`, `hg-rules`, `hg-engine`, observations and output infrastructure where their contracts fit. Add engine/core capabilities only through a bounded, separately tested opt-in seam. Do not fork a second simulator or duplicate the LK workspace into the root dependency graph.

Separate four identities in every artifact: immutable physics version, experimental profile/configuration, evolving material state, and observer/assay version. Material operators alter effective local behavior under a fixed bounded interpreter; they do not edit the interpreter's laws or obtain free capabilities from cached host metadata.

Keep old D0/ERE checkpoint codecs and profiles readable unchanged. New chemistry checkpoints need a new magic/schema and strict mismatch rejection. Shared engine changes require existing-profile regression checks in addition to chemical invariant tests. A serial semantic reference precedes concurrent execution or accelerators.

## 7. Experimental contract requirements

Each executable milestone freezes hypothesis, initial conditions and origin labels, law/config/source/binary hashes, world panel and denominator, physical-time horizon, engineering event/storage limits, observation windows, intervention selection rule, complete assay panel, acceptance criteria, and independent checker version before outcomes. Include a resource estimate for native execution **and** independent audit.

Distinguish authored initialization, assisted handoff, autonomous construction, and intervention. Never silently replace an extinct, unreachable, malformed, capped or failed world. Report mechanisms conditional on exposure as secondary analyses while preserving the full launch denominator. Statistical inference clusters by independent world, not by every related birth or reaction.

When an engineering limit binds, halt with an explicit incomplete status and retain the partial trajectory. Do not truncate candidate enumeration and interpret the resulting biased chemistry as normal execution. A scientific null, valid dominance result or sterile neighborhood does not justify changing criteria mid-run.

Interventions require predeclared target selection and branch checkpoints, sham/matched material-energy controls, and complete branch provenance. Shared initial seeds do not ensure identical random-number consumption after branches diverge. Use declared counter-based stream identities and record their coupling semantics.
