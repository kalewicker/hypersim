## What is implemented

The [frozen numerical plan](ere_categorical_comparison_v1.md), its JSON design,
all four planning sources and nine-entry preregistration archive are unchanged.
The [harness contract](ere_categorical_comparison_harness_v1.md) explains launch,
source, accounting, resource and evidence boundaries.

The isolated [Rust comparison module](../crates/hg-train/src/ere/categorical_comparison.rs)
and [binary](../crates/hg-train/src/bin/ere-categorical-comparison.rs) implement:

- Exact native science/development schedules and separate seed domains.
- Independent A/B ES noise identities; unchanged antithetic candidates and
  candidate-batch ordinal/rank update; the existing raw categorical LOO adapter.
- Group-centered fixed-radius proposals, explicit f32 rounding, exact reversal
  construction, degeneracy retention and actual step ceilings.
- All-group/full-leaf probability normalization and ratio bounds before validation.
- Shared, fresh base-only validation with four physics evaluations per draw,
  fixed control variate and denominators, saved weight/log-probability terms,
  and descriptive base utility/native means with honest cap nulls.
- Eight-block conjunction, fixed deadband/sign tests and development non-promotion.
- Existing guarded native evaluator and InFlight/terminal accounting, fixed
  NotRun suffixes, source/binary rechecks and cooperative resource controls.

Before each newly constructed emission is evaluated, the native code reconstructs
its exact leaf with a changed receipt-only seed and checks store canonical hash,
root, program and full emission/credit metadata equality apart from that label.
This has no Engine or RNG call. Its native execution remains unexercised until
the development fixture; the source is bound and the expected complete counts
are enforced (144 development, 6,144 science). The evaluator source accepts only
emitted store/program and physics seed, not logits or the receipt emission seed.

The [preparation/launch driver](../scripts/run_ere_categorical_comparison.py)
defaults to zero work. It validates source/lineage identities, checks explicit
historical schedule seed collisions, builds with only `ere-complete-signal` and
no default features, checks sources before/after compilation, and freezes all
inputs before simulation. Source/lineage checks, build and freezing count toward
setup wall time. The native entry point requires an explicit launch bit, immutable
prepared root, exact config hash and registered native schedule, fresh initial
manifest, and a successful frozen zero-work preflight before grammar compilation.

Science execution also requires a completed, sealed, source-identical development
receipt with six detached tamper controls. Its root is bound into immutable
science inputs and re-audited before any science work. This is an engineering
prerequisite, not an extra scientific outcome-selection criterion.

The [independent Python auditor](../scripts/audit_ere_categorical_comparison.py)
reconstructs native receipt accounting through sealed historical helpers, both
raw update formulas, proposal bits, all support/weight calculations, four-physics
means, importance effects and fixed statistics. It checks full allocated slots,
prefix order and validation-after-all-directions. It does not independently
replay Engine, compiler or random draws. Seed identities are bound; sampled
noise and selections are not independently regenerated by this auditor.
