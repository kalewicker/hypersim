## Gate and seed behavior

Every bridge preflight binds the exact completed development root and successful
storage-verification v4 root. It verifies original complete/known development,
six original detached controls, the storage receipt's 27 groups/14 controls,
saved/recomputed development audit equality and the explicit source relationship.

An authorized future science request must additionally supply a sealed, audited
**source- and binary-identical zero-work bridge preflight**. Its fixed schedule
must remain entirely NotRun and its manifest equal its initial manifest. This
binds all nine added files and both new exports, not only the unchanged physics.
A receipt with empty root, wrong mode, changed sources/binary, native work or
missing bridge audit cannot be used as that preflight.

The former launcher's all-modes seed check was blocking science on used
development seeds. The new inventory checks **only the selected mode** against
all conservative prior reservations, across seed roles. Current scope finds
seven prior list-schedule archives and **4,434 explicit IDs**; scientific IDs do
not collide. Development reuse still rejects. No seeds were replaced or consumed.

Completed/ambiguous histories and explicitly authorized prepared requests reserve
their full listed schedules, including NotRun suffixes. Only a strict, explicitly
unauthorized zero-work manifest is skipped. Missing metadata, boolean counters,
malformed seed types/ranges and symlinks never justify a skip. Metadata and
schedule hashes are recorded; the candidate inventory is rechecked immediately
before native execution and by the frozen auditor, excluding its own schedule.
This assumes serialized launch; it is not an atomic multi-process seed allocator
or a proof about implicit historical RNG streams.

## Verification results

- **Eleven new Python groups pass**, also rerun from the frozen preflight test
  source. They cover registration, AST/source invariance, selected-mode domains,
  authorized reservations, strict zero-work skips, ambiguous/bool metadata,
  cross-role collisions, bad seeds/symlinks/history changes, drift/broadened
  exports, old/new native offline math equality, and driver/gate refusals.
- **Four copied Rust regression groups pass**: exact preregistered schedules,
  centered/rounded radius and reversal, missing/development/conjunction statistics,
  and zero-work refusal. The feature-disabled Cargo check also passes.
- The new binary's deterministic offline fixture exactly matches the preserved
  original binary's full result, including both contexts and full-support ratios.
  It performs no Engine steps or grammar compilation.
- **Twelve detached semantic mutations reject**: false support, training admission,
  attempt count, schedule seed, full-training authorization, default features,
  both gate roots, a source waiver, seed mode, numerical radius and in-flight work.
  Prepared hashes/seals are updated on each disposable copy, so these are semantic
  refusals rather than stale-checksum refusals.
- Actual native `run-prepared` rejects the genuine false-authorization preflight;
  native `check-prepared` rejects a wrong root. Both leave its seal unchanged.
- On a disposable, re-pinned synthetic true-bit fixture referencing the real
  zero-work parent, **only `check-prepared`** is invoked. It successfully exercises
  the native dispatch to the frozen bridge checker, then returns zero evaluations,
  steps, grammar compilations and updates. No true-bit `run-prepared` was invoked.
  The clone remains initial-manifest-identical with no compiled grammar file.

Before freezing, development unit checks caught a malformed TOML test comment
and an exact-copy trailing-newline mismatch; both were corrected before the
final frozen tests/preflight. One early preparation attempt refused at source
registration before creating an output. There was no failed measured native run,
post-freeze checker correction, altered criterion, or outcome-dependent retry.
