## What physically prevented damage

Native request issuers at15,31,47,63 set a pending property on an isolated
live-graph threat token. At16,32,48,64 the generic damage rewrite and generic
paid absorber compete for that request and the same designated sealed payload.
The absorber has priority400 versus damage300, requires an intact payload role
and defense fuel, clears the pending request and spends exactly one unit.
It preserves the payload role. Damage clears the request and erases that role.
These are native matcher/conflict/apply operations, not host-side restorations.
Neither generic resolution rule uses a clock guard; pending live structure
triggers it. The schedule that creates requests remains explicit scaffolding.

The auditor verifies a native damage match result at each exposed resolution,
including all four funded resolutions where damage loses. It reconstructs the
losing damage binding against the same pre-step payload bound by the selected
absorber. Thus funded success does not rely on making damage inadmissible.
Disabled retains its four units but loses the rule; unpaid cannot absorb;
exhaustion absorbs twice and then admits damage. No-hazard leaves the absorber
enabled but spends nothing because no request is present.

All seeded editors remain META-visible with no blanket node-label ceiling/A2
protection. Defense/threat tokens are isolated from the complete rule family;
foreign metadata edges are not introduced into its encoding. Repair remains
unfunded, with no original-program restore cache. Dynamic classes, source
refreshes, canonical body identity, initial-class exclusion and actual pre-step
installed-table attribution are checked. Ordinary pairings use distinct nodes.

Aggregate ledger:10 birth payments,16 issued threats,6 absorbed threats,
10 damaging rewrite events comprising3 first lesions and7 repeated erases,
zero repair payments,5 Seal initialization payments. All nine frozen mechanism
flags pass, including admitted losing damage bindings and exact fuel controls.
