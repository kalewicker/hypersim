# Categorical comparison harness and accounting auditor v1

Prospective implementation contract, 2026-10-02. The numerical design remains
the unchanged [frozen comparison plan](ere_categorical_comparison_v1.md).
This implements a runnable isolated comparison; it does not itself authorize
development, science or training. The default command prepares and verifies a
zero-native-work archive. `--execute` requires separate user approval for the
selected mode. A preparation receipt is not development or scientific acceptance.
Scientific execution additionally requires a complete, sealed, source-identical
development archive with six detached tamper controls. Its receipt is bound into
the immutable launch inputs and re-audited before science can start. Native
startup also invokes the frozen accounting checker on the zero-work preparation
before compiling the grammar; forged or incomplete source/launch bindings fail
before Engine work.

## Components and launch boundary

`categorical_comparison.rs` owns fixed schedules, estimates, matched f32 proposals,
full-support ratios, base-only validation and fixed-block statistics. It calls
the unchanged `feasibility_training::Runner` for native evaluation and durable
InFlight/terminal receipt accounting; native physics/reward/null semantics are
not reimplemented. ES and categorical raw updates use their existing modules.

`run_ere_categorical_comparison.py` checks the frozen plan and three historical
seals, exact additional module/binary registrations and all other in-scope source
hashes. It builds only `ere-complete-signal`, without default features or
evolving-minds, and checks all source hashes before/after compilation. It freezes
472 sources, build/source receipts, the executable, config, contexts and exact
schedule before any simulation. The five prospective excluded evolving-minds
paths remain excluded; no shared-source drift is silently accepted. A separate
immutable prepared-input seal binds these launch inputs; the native entry point
requires its exact root, an explicit launch bit, pinned config hash, native
schedule equality and fresh initial manifest before grammar compilation.

The native process compiles the grammar once; saves each started estimate before
evaluating it; evaluates all estimates and support bounds before validation;
rechecks live source/executable identities at context/block boundaries and final
completion; and commits all allocated slots, known caps, unknown cells and
NotRun suffixes. A matched proposal is external comparison arithmetic, not a
shipped optimizer change. All new source work is learning-layer, scripts or docs.

The driver scans explicit noise/emission/physics seed IDs in existing root
`output/*/schedule.json` archives before preparation. This is an explicit-schedule
collision check, not proof about undocumented implicit RNG identities. Both
new layouts are disjoint. Any collision needs a prospective revision; do not
replace seeds or retry after seeing outcomes.

## Independent accounting

`audit_ere_categorical_comparison.py` reconstructs full native accounting via
sealed historical helpers, exact source registration and launch bindings, ES
candidate/rank/update arithmetic, categorical complete-denominator LOO estimates,
matched vectors and reversals, all-group/full-leaf probability bounds,
normalization, observed leaf weight/log-probability terms, four-physics means,
importance utility/validity effects and the eight-block conjunction/sign tests.
It requires native receipts in schedule-prefix order and every expected slot;
validation cannot start before all fixed estimates/directions are saved.

The auditor uses independent Python formulas, not the Rust statistic output as
an oracle. It does not independently rerun Engine, grammar compiler or ChaCha
sampling/noise. Seed identity is bound, but random samples are not replayed by
the auditor. The existing finite f64 categorical model, not bit-exact finite-RNG
threshold differentiation, is the inferential target. Physics given a selected
leaf depends on its emitted store/program and physics seed, not logits. Native
development must verify that conditional reconstruction/noninterference before
science is recommended.
Before evaluating each newly constructed emission the native harness reconstructs
that exact leaf under a changed receipt-only seed without an RNG/Engine call,
requiring identical store canonical hash, root, program and full emission/credit
metadata apart from that label. Complete science/development require 6,144/144
such checks; they add no physics rollouts. The auditor binds the source/count,
but does not independently repeat graph reconstruction.

Known caps retain utility zero and native reuse null. An unsupported null,
panic or partial evaluation stops all future work; unknown cells keep official
means/p null. A process killed between commits retains InFlight unknown state
and cannot pass final accounting. There is no per-step crash journal or hard
OS timeout. Source/archive/resource failure cannot be repaired in a measured
archive; retain failure and separately register any correction/continuation.
