# Resource-token adapter engineering v1

Prospective boundary: zero native advances and zero optimizer updates. Import
all 16 immutable defense-allocation receipts in original order; pair their
action-independent step-13 observations into eight states. Use the previously
corrected, sealed audit for utility provenance, not for policy features.

The new `hg-train::ere::resource_adapter` leaves the old graph encoder, physics,
earlier auditors and criteria unchanged. It projects unique isolated wallet,
forecast and bounty metadata nodes by label, reading their typed properties.
IDs, input ordering, ordinary topology, scenario/action names, future receipts
and observation-wrapper convenience values are not policy features. It accepts
only step13, wallet Float0/1, forecast Int0/1 and bounty Int2/12. Pending requests
and harvested credits must both be Int0. Missing/duplicate tokens/properties,
bad references, edges touching tokens and nonempty token incidence are refused.
This is a domain-specific projection, not a general graph integrity auditor.

Four inputs are `[1, wallet, forecast, bounty/12]`; forecast/bounty/both cue masks
replace corresponding features with zero without changing wallet admission.
Four parameters define a logistic probability of defend; harvest is its
complement. Initialization is all zero (uniform), never an authored optimal
policy. A fixed nonzero probe tests arithmetic, not a fitted endpoint. Binary
actions map to the sim-core enum without running physics; both are refused when
wallet0. Probabilities and zero-gradient tied utilities for unpaid states remain
in the fixed denominator. Rejected requests do not become a third learned action.

Check 8 states ×4 modes ×2 actions =64 score-gradient/action records, plus32
expected-utility gradients. Compare analytic derivatives with independent
Python arithmetic and central differences at epsilon1e-6/tolerance2e-8. Also
check sample boundary semantics (`draw < P(defend)`), neutral outputs,
reference/order invariance, convenience/outcome-label noninterference, cue-mask
aliasing and malformed inputs. Any failure fails engineering; no retries,
endpoint selection, native execution or optimization are part of this fixture.

Archive source snapshots, exact imported inputs and their origin seal maps,
compiled test binary, test receipts and independent audit. Recheck from the
archive's own frozen verifier, copied inputs and binary, with no live source or
absolute historical-input fallback. Preserve all four original allocation
archive seals; permit only the exact additive train module export against the
314-pin accounting source package. Feature-off train checking must pass.

Passing authorizes no scientific or training claim. Next proposal, if this
passes: separately preregister a small, fixed-seed full-versus-masked learning
comparison on this authored task, with frozen utilities and all-seed reporting.
It is a contextual-bandit interface, not endogenous cognition or original ERE
gate passage. Native action timing/revalidation in a future runner remains
sim-core's responsibility.
