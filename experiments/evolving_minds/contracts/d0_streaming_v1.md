## Durable segment commits

Each fresh exclusive segment directory has immutable `segment.json`, append-only `ticks.jsonl`, immutable `checkpoint_NNNN.bin`, `state_NNNN.json` and `commit_NNNN.json`. Cursor includes segment-header SHA-256, completed tick/step, local committed tick count, byte offset, committed-prefix SHA-256 and previous published commit SHA-256. Every eight ticks and at tick 64: flush/sync complete log records; create/sync checkpoint and attestation; create/sync pending marker; publish marker exclusively; sync directory. A published marker is the commit point. Initial/start-state marker commits zero local records. Snapshot/marker/checkpoint naming and checksums must match; offsets end on complete records and ticks are contiguous. Highest published marker is authoritative for recovery; a damaged published commit rejects recovery, with no silent fallback. Pending/tail/orphan files are never promoted.

Continuations write only to a new directory. The child header links the exact source directory/commit/digest and starts at that commit's tick. Its local evidence starts at the following tick. Verify chain headers, prefix hashes, preceding commit links and checkpoint/state bindings, reject symlinks/cycles/unsupported depth, and include every committed tick exactly once across the chain. Preserve source bytes and uncommitted tails. Manifest states record normal completion or interruption; an immutable crash-state manifest captures the after-marker/before-manifest fault. Commit metadata can supersede that captured stale progress, not an arbitrary corrupt checkpoint. Maximum chain depth 8 and fixed horizon 64 in this engineering profile.
